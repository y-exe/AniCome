# コメント取得・保存

## 再生時

1. PlaybackMetadataとアプリ別Repositoryが動画アプリの作品名・話数・再生位置を解析します。
2. AppCoordinatorとRepositoryが作品・話数を照合し、選択された取得元を検索します。
3. 保存済みコメントや自動キャッシュがあれば再利用し、不足する取得元を取得します。
4. CommentTimelineが動画の尺や同期マーカーを使って取得元ごとの時刻を調整します。
5. 描画側へ反映します。追加取得で既存コメントを消さず、固定コメント・AAのコマンドや空白・改行を保持します。

ニコニコの動画情報はNCOverlay v3.40.9と同じく`responseType=json&nvpcClientVersion=1`で取得します。Watch V4の`$watchV4.data`を読み、`metadata.jsonLd.owner`の投稿者・チャンネル情報を既存の保存形式へ合わせます。旧形式と通常ページの埋め込み情報にも対応します。

取得対象は公式、dアニメ、分割・コメント専用動画、実況過去ログ、ニコ生アーカイブです。再生情報や取得元の公開状態によっては検索・同期できない場合があります。手動取得や時刻補正で調整できます。

取得量は倍率と最大件数を切り替えます。倍率のスライダーは1〜20倍、数値入力は20倍超も指定できます。最大件数は選択した取得元の合計に適用し、不足分の過去コメントを追加取得します。取得できるコメントが尽きたら終了します。過去コメントの取得にはニコニコ連携が必要です。

件数指定で保存したデータには取得時の上限を記録し、倍率指定の完全な取得結果として扱いません。上限を小さくして再生しても、既存の保存データは削除しません。

## 視聴アプリの検出

Netflix・U-NEXT・ABEMA・DMM TV・TVer・NHK ONEは標準の再生情報を利用します。Netflixは話名・話数・期から公式動画を照合し、作品を特定します。複数作品に一致する場合は自動決定しません。

次の4アプリは、初回選択時にユーザー補助を案内します。許可するまで選択は確定しません。取得対象は対象アプリの画面内の文字で、画面の撮影や操作の代行は行いません。

| アプリ | 画面に表示する情報 |
| --- | --- |
| Prime Video | 作品名・話数・再生時刻 |
| dアニメストア | 再生時刻。作品名・話数は通知から取得 |
| バンダイチャンネル | 作品名・話数。再生時刻は標準の再生情報から取得 |
| Hulu | 作品名・話数・再生時刻。プレーヤーの情報を参照し、操作表示が隠れていても時刻を取得 |

操作表示が隠れている間は取得済み時刻を基準に進めます。隠れたままのシークや通信待ちは判別できないため、操作表示を出して再同期してください。同じ秒数の再取得では時計を巻き戻さず、秒単位の表示に収まる小数秒を維持します。

Huluはプレーヤー内の話名と一致する話数情報を使い、背面の検索候補や別作品の情報を混ぜません。時計の更新から再生・停止を判定するため、一時停止の反映には最大約2秒かかります。

横画面では画面中央の16:9領域にコメントを収めます。カメラ穴やシステムバーによる片側だけの余白を描画枠へ持ち込まないようにします。

## 事前ダウンロード

作品候補から作品を確定し、APIの各話タイトル・話数とニコニコ動画の情報を照合します。期・クールや通算話数を区別し、指定した取得元を作品・話数ごとに保存します。チャンネルはURL・数値ID・スラッグでも指定できます。

保存予約はDownloadRepository・ReservationScheduler・WorkManagerが管理します。コメント本体はファイル、一覧と予約などのメタデータはRoomへ保存します。自動取得のキャッシュは手動保存と分け、期限を設定します。

保存済みファイルの読み込み・取得元の合成・別動画への差し替えを変更するときは、コメントの欠落、重複、保存データの上書き、途中での表示停止を回帰テストしてください。

## 描画と試し表示

app/src/main/assets/overlay.jsがAndroidと同梱のniconicommentsを橋渡しします。ライブラリ本体はvendor/、試し表示のコメントはニコニコ連携後に取得し、端末のfiles/preview/へ保存します。試し表示の動画本体は同梱しません。

描画テストはtests/rendering/、作品・各話の固定データはapp/src/test/resources/にあります。認証済み動画情報・個人の書き出しコメント・過去の取得作業用ファイルはGitへ追加しません。
